REST API(계정 · 문제 · 방 · 경기 기록 · 문제 등록)와 Socket.IO 실시간 이벤트(대결 진행 · 채점 결과 · 공격)를 정의합니다. v0.1 초안 — 팀 검토 필요

공통 규칙

  • 경로는 소문자 복수형 명사, 단어 구분은 하이픈(/learning-report). JSON 필드는 camelCase.
  • 목록 조회는 page(0부터), size(기본 20, 최대 100) 쿼리를 쓰고 페이지 응답으로 돌려준다.
  • ID는 문자열이다: 사용자 usr_…, 문제 prb_…, 방 코드 6자리 대문자+숫자(K7Q29X), 경기 mat_…, 제출 sub_…, 공격 atk_….
  • 규칙 수치(15분, 45초, 최대 3점 등)는 서버 설정값이다. 클라이언트는 하드코딩하지 말고 match:start의 rules를 쓴다.
  • 제출 코드 최대 64KB. 같은 사람의 제출 간격은 최소 3초(RATE_LIMITED).

한 판의 흐름

  1. POST /rooms로 방을 만들고 roomCode를 받는다. 상대에게 코드를 알려 준다.
  2. 두 사람이 소켓 room:join → 서버가 room:state를 방 전체에 보낸다.
  3. 둘 다 room:ready → 서버가 match:start(문제 5개, 시작 · 종료 시각, 규칙 수치)를 보낸다.
  4. 제출: match:submit → 서버가 submission:queued → 채점 후 submission:result(본인), opponent:progress(상대).
  5. 정답이면 서버가 포인트 계산 → 내 대기 공격 상쇄(attack:cancelled) → 남은 점수로 반격(attack:incoming, 상대에게 즉시 알림).
  6. 45초 뒤 공격 확정 → attack:applied(두 사람 모두) + 공격받은 사람에게 problem:conditions(바뀐 시간 제한 · 폭탄 · 금지 문법).
  7. 한쪽이 5문제를 다 풀거나 15분이 지나면 match:end. 이후 GET /matches/{matchId}, /learning-report로 결과를 본다.
경기 중 서버가 보내는 이벤트에는 모두 seq(경기 안 일련번호)가 붙는다. 클라이언트는 seq 순서대로 반영하고, 재접속하면 match:sync로 놓친 이벤트를 받는다. 같은 사건 기록이면 다시 보기 결과도 항상 같다.

대결 중 제출은 REST가 아니라 소켓 match:submit을 쓴다. 아래는 혼자 연습할 때만.

Socket.IO — 연결 · 공통

import { io } from "socket.io-client";
const socket = io("http://localhost:3000/battle", { auth: { token: accessToken } });
  • 토큰이 없거나 만료되면 연결이 거절된다(connect_error, message UNAUTHORIZED / TOKEN_EXPIRED).
  • 요청형 이벤트(클라이언트 → 서버)는 ack 콜백으로 결과를 받는다: { ok: true, data } 또는 { ok: false, code, message }. 코드는 에러 코드와 같다.
  • 서버 이벤트는 경기 중이면 seq와 serverTime(epoch ms)을 함께 보낸다. 클라이언트는 화면의 남은 시간을 서버 시각 기준으로 계산한다.
  • 연결이 끊기면 60초 안에 다시 붙어야 한다. 넘기면 기권(FORFEIT). 다시 붙으면 match:sync를 보내 놓친 이벤트를 받는다.

클라이언트 → 서버

C→Sroom:join1차방 입장
socket.emit("room:join", { roomCode: "K7Q29X", lang: "PYTHON" }, (res) => { ... });
// ack data
{ "roomCode": "K7Q29X", "status": "WAITING", "players": [ ... ] }

입장하면 방 전체에 room:state. 에러: ROOM_NOT_FOUND, ROOM_FULL, LANGUAGE_NOT_SUPPORTED

C→Sroom:ready1차준비 / 준비 취소
socket.emit("room:ready", { roomCode: "K7Q29X", ready: true }, ack);

두 명이 모두 준비되면 서버가 match:countdown → match:start를 보낸다.

C→Sroom:leave1차방 나가기

경기 중에 나가면 기권 처리(match:end, reason FORFEIT).

C→Smatch:submit1차대결 중 제출
socket.emit("match:submit", { matchId: "mat_1042", problemNo: 2, lang: "PYTHON", code: "..." }, ack);
// ack data
{ "submissionId": "sub_8f2c", "attackLevelAtSubmit": 2 }

서버는 제출 순간 그 문제에 걸린 공격 상태를 기록해 채점에 쓴다. 채점 도중 공격이 확정돼도 이 제출의 판정은 바뀌지 않는다. 에러: MATCH_NOT_IN_PROGRESS, ALREADY_SOLVED, RATE_LIMITED, CODE_TOO_LONG

C→Smatch:run-sample1차예제 실행 (채점 아님)
socket.emit("match:run-sample", { matchId: "mat_1042", problemNo: 2, lang: "PYTHON", code: "...", input: null }, ack);
// ack data (input이 null이면 예제 전부)
{ "results": [ { "input": "5 6\n1 2 3 4 5\n", "expected": "2\n", "actual": "2\n", "verdict": "AC", "timeSec": 0.02 } ] }

오답 횟수에 세지 않고, 공격 · 포인트와 무관하다.

C→Smatch:sync1차재접속 후 상태 복구
socket.emit("match:sync", { matchId: "mat_1042", lastSeq: 41 }, ack);
// ack data
{ "events": [ { "seq": 42, "type": "attack:applied", "payload": { ... } } ], "snapshot": { ... } }

snapshot은 현재 경기 전체 상태(match:start 형식 + 문제별 공격 단계 + 대기 공격 + 남은 시간).

C→Sspectate:join최종관전 입장
socket.emit("spectate:join", { roomCode: "K7Q29X" }, ack);

관전자는 모든 경기 이벤트를 받는다. 양쪽 코드는 spectate:code로 30초 늦게 받는다(엿보기 방지).
